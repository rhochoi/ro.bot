# ro (rogbot) 설계 청사진 v0

> 층 셋, 눈 둘. 기록하고, 풀어낸다.
> 에이전트는 **하나(ro)**. Claude·Codex·agy는 ro가 상황에 따라 부르는 **엔진**이다.

## 1. 원칙

1. **단일 인격**: 사용자는 ro와만 대화한다. 엔진 선택은 ro의 내부 결정이다.
2. **기록이 먼저**: 모든 행동은 로그(층)로 남고, 가장 최근 기록이 가장 길다(브랜드 = 구조).
3. **읽기 우선, 쓰기는 승인**: 로컬 되돌릴 수 있는 수정만 자율. 외부 전송·삭제·구매·계정·보안은 직전 승인 (`~/.codex/AGENTS.md` 권한 규칙 상속).
4. **비밀 불저장**: 비밀번호·키·토큰은 기억·로그 어디에도 남기지 않는다.
5. **증거 > 기억**: 기억은 힌트, 현재 상태 확인이 우선.

## 2. 구조 (층 셋 = 3 레이어)

| 층 | 역할 | 구현 |
|---|---|---|
| 머리 (Head) | 의도 파악, 라우팅, 승인 게이트 | `ro` 오케스트레이터 (정책 + 라우터) |
| 몸 (Body) | 컴퓨터 이해: 프로젝트·도구·설정 지도 | `map/` 읽기 전용 스캔 → 구조화 인덱스 |
| 바닥 (Base) | 기록: 이벤트 로그, 결정, 선호 | `log/` append-only (JSONL) + 요약 |

엔진 어댑터(`engines/`): `claude`, `codex`, `agy` 각각 동일 인터페이스
`run(task, context, mode: read|write) -> result + evidence`.

## 3. 엔진 라우팅 (초기 가설, 로그로 교정)

- 장문 맥락·설계·리뷰 → claude
- 저장소 단위 구현·테스트 반복 → codex
- 에디터/브라우저 연동 작업 → agy
- 판단 근거와 결과(성공/실패/비용)를 매번 기록 → 라우팅 규칙을 데이터로 갱신

## 4. 개인화 발전 단계 (각 단계 30분 단위로 분할)

0. **Seed**: 이 문서, 정책, 로그 스키마. (현재)
1. **Map**: `~/Claude`, `~/Downloads`, `~/.codex` 등 읽기 전용 스캔 → 프로젝트·도구 지도 생성 (비밀 파일 제외 목록 포함).
2. **Log**: 모든 ro 작업을 JSONL로 기록, 일일 요약 생성.
3. **Route**: 엔진 어댑터 3종 + 수동 라우팅 → 로그 기반 추천 라우팅.
4. **Learn**: 반복 수정·선호를 후보로 제안 → 사용자 승인 후에만 규칙화.
5. **Harden**: 평가 체크리스트(회귀), 권한 감사, 실패 재현 테스트.
6. **Ambient**: 장치(시리얼 `serial_link.py` 등)·알림·일정 입력 채널 확장.

각 단계 종료 조건: 실행·검증 증거 + 롤백 방법.

## 5. 브랜드 → UI 매핑

- 표정: 기본 / 기록 중 / 집중 / 불안(권한 필요·오류) / 발견 / 풀어냄(완료)
- 상태 표시 = 층 애니메이션 (로딩 = 바닥 층이 자란다)
- 색은 둘(검정·크림), 아이콘은 16px 전용 버전
