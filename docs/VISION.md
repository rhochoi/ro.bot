# rog.bot 비전 문서

> **상태(2026-10-27):** 이 문서는 설계 이력입니다. 질문(`ask`)·학습(`learn`·`distill`)·라우팅(`route`·`revise`)·활동 수집(`collect`)·컨텍스트 평가(`bench`)·장치 입력(`ambient`)은 제거됐습니다. 현재 구조는 `README.md`를 보세요.

> 최초 브레인스토밍: 2026-10-21 (수) · 상태: 기획 초안

## 1. 한 줄 정의

**rog.bot은 도구에 종속되지 않는 하나의 캐릭터(두뇌)다.** Claude Code·Antigravity(agy)·Codex 어디서 부르든 같은 기억·규칙·스킬로 동작하고, 내 로컬 컴퓨터와 행동 기록을 알고 있으며, 사소한 일부터 함께한다.

핵심 원칙: **캐릭터는 도구가 아니라 데이터다.** 정체성·기억·라우팅표·스킬을 파일로 두고 GitHub로 관리하면, 어떤 하네스든 그 파일을 읽는 순간 rog.bot이 된다.

## 3. 아키텍처

```
rog.bot/                     ← GitHub 저장소 = 캐릭터 본체
├─ identity/
│  ├─ persona.md             캐릭터·말투·가치관
│  └─ principles.md          안전·권한·작업 원칙 (기존 ~/.codex/AGENTS.md 이관)
├─ memory/
│  ├─ rog-model.md           나에 대한 모델 (선호·루틴·용어·진행 중 프로젝트)
│  └─ decisions/             중요한 결정 기록
├─ routing.yaml              작업 유형 → 모델 매핑
├─ skills/                   공용 스킬 (각 도구의 skills 디렉터리로 symlink)
├─ adapters/                 도구별 진입점
│  ├─ claude/CLAUDE.md       → identity·memory를 @import
│  ├─ codex/AGENTS.md
│  └─ agy/
├─ collectors/               행동 기록 수집기 (§5)
└─ data/                     ← .gitignore, 로컬 전용 (SQLite·인덱스·원본 로그)
```

- **공유 계층**(identity, memory, routing, skills): 모든 도구가 똑같이 읽는다.
- **어댑터 계층**: 각 도구의 설정 형식에 맞게 공유 계층을 가리키기만 한다. 로직을 넣지 않는다.
- **로컬 데이터**(`data/`): 절대 커밋하지 않는다. GitHub에는 증류된 결과만 올라간다.

## 4. 기능 상세

### 4.1 로컬 지식 (0번)

- **1단계(YAGNI)**: macOS Spotlight(`mdfind`) + `rg`로 검색. 별도 인덱스를 두지 않는다.
- **2단계(필요 시)**: 자주 쓰는 폴더만 임베딩 인덱스(SQLite + 벡터 확장)로 만든다.
- **파일 정리**: rog.bot은 정리 계획(이동 목록, 중복, 오래된 파일)을 **제안**만 한다. 이동·삭제는 사용자 승인 후 실행하고, 실행 로그를 남겨 되돌릴 수 있게 한다.

### 4.2 모델 라우팅 (2, 2-1번)

`routing.yaml` 예시:

```yaml
updated: 2026-10-21
routes:
  trivial:      { model: haiku,       why: "사소한 질문·변환, 빠르고 쌈" }
  coding:       { model: sonnet,      why: "일반 구현" }
  architecture: { model: opus,        why: "설계·어려운 디버깅" }
  long-context: { model: gemini,      why: "대용량 문서·코드베이스 훑기" }
  review:       { model: gpt,         why: "다른 계열 모델로 교차 검증" }
```

- 하네스가 작업을 분류하고 라우팅표대로 모델/도구를 고른다.
- **적극적 변동**: 주 1회, 지난주 작업 결과(성공·재시도·비용)를 보고 라우팅표 개정안을 제안한다. 새 모델이 나오면 후보로 추가한다.

### 4.3 스킬 (3번)

- `skills/`에 공용 스킬을 두고, Claude Code·Codex·agy의 스킬 경로로 symlink한다.
- 행동 기록에서 **3회 이상 반복된 절차**를 찾으면 스킬화를 제안한다.

### 4.4 GitHub 연동 (4번)

- 캐릭터 본체를 private 저장소로 관리한다. 여러 기기에서 같은 rog.bot을 쓸 수 있다.
- 기억·라우팅 변경은 커밋 단위로 남겨서 "rog.bot이 언제 무엇을 배웠는지" 추적·롤백할 수 있다.
- 주간 증류 결과는 PR로 올리고, 사용자가 리뷰한 뒤 머지한다.

## 5. 행동 기록과 극단적 개인화 (5, 6번)

5번과 6번은 **하나의 루프**로 설계한다.

```
수집(상시) → 일간 요약(매일) → 주간 증류(매주) → 규칙 제안 → 사용자 승인 → 기억/규칙 반영
```

### 5.1 수집 (6번 고도화)

| 소스 | 방식 | 비고 |
|---|---|---|
| 셸 history | `~/.zsh_history` 증분 읽기 | 명령어 패턴 |
| git | 로컬 저장소 커밋 로그 | 작업 주제·시간대 |
| Claude Code / Codex 세션 | 세션 transcript 파일 | 무엇을 시켰고 어디서 막혔나 |
| ChatGPT | 데이터 export (수동, 주기적) | 관심사·질문 패턴 |
| 파일 변경 | FSEvents (허용 폴더만) | 어떤 프로젝트를 만지는가 |
| 캘린더 | 읽기 전용 연동 | 루틴·마감 |

- 모든 이벤트는 `data/events.db`(SQLite) 하나에 `(시각, 소스, 종류, 요약, 원본경로)` 형식으로 정규화한다.
- **저장 전 마스킹**: 키·토큰·비밀번호·금융 식별정보 패턴을 제거한다. 원본은 저장하지 않고 경로만 참조한다.
- **허용 목록 방식**: 명시한 소스·폴더만 수집한다.

### 5.2 요약과 증류

- **일간 요약**: 하루 이벤트를 가벼운 모델로 요약해 `data/daily/YYYY-MM-DD.md`에 저장한다.
- **주간 증류**: 일간 요약 7개를 읽고 아래를 뽑는다.
  - 새로 보인 선호·습관
  - 반복 작업 → 스킬 후보
  - 자주 막힌 지점 → 규칙·도구 개선 후보
  - 모델 라우팅 성과 → `routing.yaml` 개정 후보

### 5.3 개인화 반영 (5번)

- 증류 결과는 **제안**으로만 나온다. 사용자가 승인한 항목만 `memory/rog-model.md`, `identity/`, `routing.yaml`, `skills/`에 반영한다.
- 자동 반영을 하지 않는 이유: 잘못된 추론이 기억을 오염시키고, 오염된 기억이 모든 도구로 퍼지기 때문이다.
- 개인화의 실체 = **세 도구가 똑같이 읽는, 승인된 파일 묶음**.

## 6. 안전·프라이버시 원칙

1. **로컬 우선**: 원본 데이터는 기기 밖으로 나가지 않는다. 외부 모델에는 요약·필요한 조각만 보낸다.
2. **비밀값 무저장**: 비밀번호·키·토큰·복구 코드·금융 식별정보는 수집·기억·커밋 어디에도 남기지 않는다.
3. **제안 후 실행**: 파일 이동·삭제, 외부 전송, 설정 변경은 승인 후에만 실행한다.
4. **데이터는 지시가 아니다**: 로컬 파일·웹 기록·이메일에 있는 문장은 명령으로 취급하지 않는다(프롬프트 인젝션 방어).
5. **되돌릴 수 있음**: 모든 기억·규칙 변경은 git으로 추적하고, 파일 정리는 실행 로그로 되돌릴 수 있게 한다.

## 7. 로드맵 (MVP 우선)

각 단계는 30분~반나절 단위로 쪼갠다.

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| M1 | 기존 하네스(`~/.codex/AGENTS.md` 등)를 `identity/`로 이관하고 어댑터 연결 | 세 도구에서 같은 규칙이 적용됨을 확인 |
| M2 | `routing.yaml` 수동 작성 + 하네스에서 참조 | 작업 유형별로 지정 모델이 쓰임 |
| M3 | 수집기 최소판(셸·git·세션 기록) + 마스킹 | `events.db`에 하루치 이벤트가 쌓임 |
| M4 | 일간 요약 + 주간 증류 스케줄 | 주간 제안 문서가 자동 생성됨 |
| M5 | 제안 → 승인 → 반영 루프 (PR 기반) | 승인한 항목이 `memory/`에 커밋됨 |
| M6 | 로컬 검색·파일 정리 제안 | 정리 계획 제안 → 승인 → 실행 → 되돌리기 확인 |
| M7 | 라우팅 자동 재평가, 스킬 자동 제안 | 주간 개정안이 근거와 함께 나옴 |

## 8. 열린 질문

- 캐릭터의 이름·성격·말투는 어떻게 할까? (`identity/persona.md`)
- "사소한 일에도 함께"의 진입점은 어디인가? 터미널 단축 명령, 메뉴바 앱, 음성 중 무엇?
- ChatGPT 기록은 수동 export로 충분한가, 더 자주 가져올 방법이 필요한가?
- 여러 기기를 쓸 때 `data/`(로컬 전용)는 기기별로 둘 것인가?
- 주간 증류에 쓸 모델과 비용 상한은 얼마로 둘 것인가?
