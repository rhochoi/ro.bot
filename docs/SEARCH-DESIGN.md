# ro find 설계안 — "그때 필요한 그 파일"을 찾아주기

작성: 2026-10-26 · 상태: **설계 단계(미구현)**. 결정 필요 항목은 §7.

## 1. 목표와 완료 조건

사용자가 파일 이름을 기억하지 못해도, **기억나는 단서**(언제·어디서·무슨 내용·무슨 종류·누구와)로 파일을 찾는다.
안전 약속은 organize와 같다: **읽기 전용, 원본 내용은 기기 밖으로 나가지 않음, 결과는 후보 목록으로 제안.**

완료 조건(1차): 아래 §3의 대표 질문 10개에 대해 정답 파일이 상위 5개 안에 나오는지 `ro eval`로 측정해 8개 이상 PASS.

## 2. 확인한 사실 (2026-10-26)

- [docs/VISION.md](VISION.md) 4.1이 이미 정함: 1단계는 `mdfind`(Spotlight) + `rg`, **별도 인덱스 없음**. 2단계는 필요할 때만 임베딩 인덱스.
- 이 맥에서 `mdfind`는 동작하고 한글 이름도 찾는다(한글 파일명 검색 확인).
- `fd`·`fzf`는 설치돼 있지 않다. `rg`는 있다. → 새 설치 없이 `mdfind`·`rg`·표준 라이브러리로 1단계 가능.
- 재사용할 코드: [ro/tidy.py](../ro/tidy.py)의 `walk`(숨김·비밀·프로젝트 폴더·심링크 제외), [ro/mapper.py](../ro/mapper.py)의 `is_secret`,
  [ro/organize.py](../ro/organize.py)의 텍스트 추출(PDF·docx·hwpx), `log.redact`, [ro/recall.py](../ro/recall.py)의 기간 해석(`_scope`).

## 5. 해결 방식 — 4단 구조 (싼 것부터, 못 찾을 때만 다음 단계)

```
질문 ─▶ [Q] 질의 해석 ─▶ [S1] 메타데이터/이름 ─▶ [S2] 본문 ─▶ [S3] 의미(선택) ─▶ [R] 정렬·필터 ─▶ 후보 + 이유
```

**Q. 질의 해석 (규칙 우선, LLM 없이 시작)**
- 한국어/영어 질문을 `{이름조각, 본문구절, 기간, 종류, 위치, 제외, 사람}`으로 분해. 기간은 [ro/recall.py](../ro/recall.py)의 `_scope` 확장.
- 해석이 애매하면 **해석 결과를 먼저 보여주고** 확인("지난주 · PDF · '계약서'로 찾을게요").
- 외부 LLM 사용 시 질문 문장만 마스킹해 보낼 수 있고 **파일 내용·경로 목록은 보내지 않는다.** 1차는 LLM 없이 규칙만.

**S1. 메타데이터/이름 (즉시, 인덱스 불필요)** — `mdfind`로 이름·날짜·UTI·출처·작성자 조건 질의. NFC/NFD 둘 다 시도, 초성 일치는 후처리.

**S2. 본문** — Spotlight가 본문을 이미 색인한 파일은 `mdfind` 그대로. 색인 밖(숨김 아닌 일반 폴더의 텍스트·코드)은 `rg`.
PDF·docx·hwpx는 organize의 추출기를 재사용하되 **결과를 `~/.ro/cache/`에 파일 해시 키로 캐시**(ripgrep-all 발상).

**S3. 의미 검색 (2단계, 선택)** — "표현을 모르는" 질문(C)과 이미지(H)용. 자주 쓰는 폴더만 SQLite FTS5(+벡터 확장)로 색인,
**임베딩은 로컬 모델만.** 모델 설치는 사용자 승인 사항. 1단계 평가에서 C 유형 실패가 많을 때만 착수.

**R. 정렬과 안전 필터**
- 점수 = 이름 일치 + 본문 일치 + 기간 일치 + 최근 열람 가중 + 종류 일치. 각 후보에 **왜 나왔는지 한 줄**("이름에 '계약서', 지난주 수정, PDF").
- 비밀 파일(`is_secret`)·`.ssh`·키체인·`.env` 등은 결과에서 제외. 경로 표시는 `log.redact` 통과.
- 같은 계열 버전(`_final`, `_최종2`)은 묶어서 최신을 위로.
- 0건이면 조건을 하나씩 완화해 보여주고("PDF 조건 빼면 3건"), 너무 많으면 좁히기 질문 1개만(M).
- 결과 동작은 **열기·Finder에서 보기·경로 복사**까지. 이동·삭제는 하지 않는다(그건 organize/tidy의 승인 흐름).

## 7. 결정이 필요한 것 (내 기본안 포함)

1. **1차 검색 범위:** 홈 전체 vs `Downloads/Documents/Desktop/iCloud` 한정. *기본안: 한정 폴더 + 사용자가 추가.*
2. **질의 해석에 LLM을 쓸지:** *기본안: 1차는 규칙만, 규칙이 못 푸는 질문만 마스킹된 문장으로 외부 LLM 허용(승인 후).*
3. **의미 검색(S3) 도입 시점:** *기본안: F0 평가 결과를 보고 결정(지금 설치 안 함).*
4. **UI 진입점:** CLI 먼저 vs 펫 입력창 먼저. *기본안: CLI → 펫.*

## 8. 위험

- Spotlight 색인이 꺼진 폴더/외장 디스크는 못 찾는다 → F1에서 "색인 안 됨" 경고와 `rg` 폴백.
- iCloud 미다운로드 파일은 본문을 읽을 수 없다 → 이름·메타데이터만으로 표시하고 "내려받기 필요" 표기.
- `mdfind` 질의 문법은 OS 버전에 따라 달라질 수 있다 → 질의 생성 함수에 단위 테스트.
- 평가 세트가 내 개인 파일이라 공개 저장소에 못 올린다 → 경로·정답은 `~/.ro/`에, 저장소에는 형식만.

## 9. Codex 재감사 반영 (2026-10-26) — 판정: **수정**

감사 원문은 세션 스크래치패드(`audit-result.md`)에 있고, 아래는 내가 직접 재확인한 것과 설계 변경이다.

**직접 재확인한 사실**
- `tidy.walk()`는 `.git`·`pyproject.toml` 등이 있는 폴더를 통째로 건너뛴다([ro/tidy.py:55](../ro/tidy.py)) → 코드 검색(I)에 그대로 못 쓴다. 검색용 탐색기는 따로 만든다.
- FTS5 `trigram`은 `개인업무계약서`에서 `계약`(2글자)은 0건, `계약서`(3글자)만 1건 → 짧은 검색어·초성·NFD는 별도 설계 필요.
- organize의 추출기는 요약용이라 PDF 앞 2쪽·본문 2,048자 등으로 잘린다 → 전문 검색에 못 쓴다. 검색용 추출을 분리한다.
- 이 맥의 Spotlight는 켜져 있고 `mdfind`도 동작한다(`mdutil -s /` → Indexing enabled). Codex 샌드박스에서는 "disabled"로 보였으니 **샌드박스 한계로 판단**하고 일반화하지 않는다. 다만 Downloads 파일의 `kMDItemLastUsedDate`는 null이었다 → 날짜·열람 신호는 파일마다 없을 수 있다고 가정한다.
- ripgrep-all 라이선스는 AGPL-3.0-or-later로 정정(§4 표).

**설계 변경 (우선순위)**
1. **P0 안전·실패 구분:** 안전 필터를 **읽기 전·캐시 전**(맨 앞)으로 이동한다. 허용 폴더·사용자 제외·비밀 차단은 조건 완화로 풀지 않는다.
   결과 없음은 "서비스 불가 / 범위 밖 / iCloud 미다운로드 / 추출 실패 / 진짜 0건"으로 구분해 표시한다. `is_secret`은 이름 패턴뿐이라 `recovery-codes.txt`를 못 거른다 → 키워드 확장.
   `log.redact`는 개인정보 익명화 도구가 아니다 → 경로 표시는 홈 기준 상대경로로 줄인다.
2. **P1 후보 누락 해결:** Spotlight 후보에만 퍼지 점수를 매기면 처음에 빠진 파일은 복구 못 한다. **허용 폴더의 파일명 직접 열거(NFC 정규화, 초성, 2글자 부분문자열)를 1차부터** 넣고 Spotlight는 보조 검색원으로 둔다.
3. **P1 본문 계약:** 형식별 지원 범위(PDF/docx/hwpx 가능, HWP·Pages 미지원)와 잘림 여부를 결과에 표시. 전문 검색용 추출은 organize와 분리.
4. **P1 평가:** `ro eval`은 안전 불변식 검사기라 검색 품질 평가기가 아니다. 파일 식별자 기반 평가를 새로 만들고, 유형별 상위 5개 적중률·후보 누락·잘못된 "없음"·지연·비밀 노출을 잰다. 튜닝에 안 쓴 별도 질문도 남긴다.
5. **P2 조건부 확장:** 반복 본문 검색이 느릴 때만 선택 폴더 FTS(캐시는 새 민감 사본이므로 권한 0600·보존기간·범위 철회 시 삭제 정의 후) → 표현 불일치가 남으면 의미 검색 → 질의 해석 실패가 남으면 로컬 LLM.

**유형 보강:** 태그·식별자(문서번호), 컨테이너 내부 위치(시트·슬라이드·ZIP 안), OR·괄호·후속 대화("그중 지난달 것"), 사건 상대 시간, 작성자≠보낸 사람·수정일≠받은 날·최신≠승인 최종본 구분을 A~N에 추가한다.
N(존재 확인)은 비교 대상이 없으면 해시가 아니라 "확인한 범위"를 함께 답한다.

**대안 판정:** 검색 에이전트는 기본 고정 파이프라인 + 어려운 질문에만 호출 수·시간·폴더 제한 보조 탐색(임의 셸 생성 금지). 열람 로그는 ro에서 사용자가 연 파일의 최소 이벤트만, 약한 순위 신호로 쓴다(현 `recall`은 파일 열람 기록이 아님).
과잉 설계로 제외: 전역 벡터 DB, 상시 화면·열람 감시, 무제한 검색 에이전트, 전 파일 선제 해싱.

**권장 흐름 (§5 대체):** `범위·민감정보 차단 → 질의 해석 → 파일명 열거 + Spotlight + 필요한 본문 검색 → 후보 병합 → 조건 검사·순위 → 근거와 검색 한계 표시`
