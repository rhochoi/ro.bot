## 1. 한 줄 방향

비전의 핵심은 "캐릭터는 도구가 아니라 데이터다". 지금까지 `ro`는 **동작하는 CLI 뼈대**(지도·질문·기록·학습·점검·측정)를
만들었고, 비전에서 비어 있는 것은 **캐릭터를 파일로 두고 세 도구가 같이 읽게 하는 층(M1·M2)** 과
**행동 기록 수집·증류(M3·M4)** 이다. 순서는 "작고 위험이 낮고 측정 가능한 것부터".

## 4. 단계별 로드맵

각 단계는 30분~반나절 단위로 쪼개고, 종료 조건은 `ro eval`·`ro audit`·`ro bench` 또는 직접 실행 증거로 확인한다.

| 단계 | 내용 | 종료 조건 |
|---|---|---|
| **Phase 0** | VISION 통합 + 매핑표 + 이 문서 | 한 브랜치에서 비전·구현·방향이 함께 보임 |
| **Phase 1** (M1+M2) | 얇은 어댑터 3종 + `routing.yaml`, `route.py`의 코드 규칙을 데이터로 이관 | 세 도구에 같은 탐침 질문(규칙 확인)을 읽기 모드로 던져 일치 확인 |
| **Phase 2** (M3) | 수집기: git → 셸(atuin 읽기 전용) → 엔진 세션 기록. 마스킹·허용 목록 | 하루치 이벤트 적재, `ro audit` 통과, 비밀 패턴 0건 |
| **Phase 3** (M4+M5) | 로컬 일간 통계·주간 증류를 `learn` 후보로 연결, 승인한 항목만 `memory/`에 반영 | 후보 → 승인 → 커밋 한 사이클 |
| **Phase 4** (M6) | 읽기 전용 중복·오래된 파일 보고서 → 되돌림 로그 → 승인 후 실행 | 제안 → 승인 → 실행 → 되돌리기 확인 |
| **Phase 5** (M7) | 로그와 `bench`로 라우팅 개정안 자동 제안 | 근거(성공·재시도·비용) 포함 개정안 |

M3(측정)를 M1보다 앞세울 수도 있으나, M1·M2는 작고 위험이 낮으며 `bench`로 효과를 잴 수 있어 먼저 간다.

### Phase 1 구현 메모 (2026-10-21)

- **`routing.yaml` 대신 `routing.toml`**: Python 3.11+ 표준 라이브러리(`tomllib`)로 읽혀 의존성이 없다. 파일이 없거나 틀리면 경고 후 내장 기본값으로 동작.
  `model`이 빈 문자열이면 엔진 기본 모델(모델 이름은 확인 후에만 채운다). 엔진을 수동으로 바꾸면 모델은 적용하지 않는다.
- **`adapters/` 디렉터리 대신 저장소 루트의 `AGENTS.md`·`CLAUDE.md`**: 도구가 작업 폴더 루트에서 찾기 때문. 둘 다 `identity/principles.md`에서
  `python -m ro.adapters build`로 생성하는 파일이며 직접 고치지 않는다(`check`와 단위 테스트가 드리프트를 잡는다).
  codex·agy용 `AGENTS.md`는 `@import`가 없어 원칙 본문을 포함하고, `CLAUDE.md`는 `@identity/principles.md` 포인터다.
- **전역 설치는 자동으로 하지 않는다.** `~/.codex/AGENTS.md`·`~/.claude/CLAUDE.md` 수정은 지속 설정 변경이라 사용자 승인 뒤에만 한다.
  이 저장소 폴더에서 도구를 실행할 때만 어댑터가 적용된다.
- **확인 방법**: `python -m ro.adapters probe --engine <엔진>` — 같은 질문(식별 문구)을 저장소 폴더와 빈 폴더에서 던져
  저장소에서만 답이 나오는지 본다. 한계: 지시로 파일 읽기를 막았을 뿐이라 정황 증거다.
- **확인 결과 (2026-10-21)**: codex — 저장소 폴더에서 식별 문구 응답, 빈 폴더에서 '모름'(통과, 11초/8초).
  agy — 동일하게 통과(47초/47초). **claude는 로그인 만료로 미확인**(`CLAUDE.md` 생성·import 문법만 확인).
- **발견한 결함**: 엔진 하위 프로세스가 부모 stdin을 물려받아 멈추는 문제(600초 시간 초과 3회로 추정). `route.run`이 stdin을 닫도록 고침.

### Phase 2 구현 메모 (2026-10-21)

- **수집기** `python -m ro.collectors allow|deny|status|run` — git → 셸 → 엔진 세션(codex·claude). 결과는 `kind="activity"` 이벤트(JSONL, 이벤트 시각 기준 일자 파일).
  SQLite 이전은 보류(§3-5): 아직 JSONL로 충분하고 이벤트 수가 적다.
- **허용 목록이 기본값**: `~/.ro/collect.json`에 `allow`한 소스만 읽는다. 처음엔 아무것도 읽지 않는다.
- **최소 수집**: 셸은 프로그램·하위 명령만(인자·경로·환경변수 값 버림), 세션은 메타데이터만(턴·도구 호출·오류 수, 폴더 이름;
  대화 내용·계정 식별자·지침 본문은 읽어도 저장 안 함), git은 본인 커밋 제목만. 대화 내용(프롬프트) 수집은 후속 결정 사항.
- **증분·멱등**: 커서 `~/.ro/collect_state.json`. 진행 중인 세션(30분 내 변경)은 건너뛰고, 끝난 세션이 이어져 커지면 `rev`를 올려 다시 기록(통계는 같은 `ref`의 최신 rev만).
- **agy 세션은 형식 미확인으로 미지원**. 앱 사용 시간·ChatGPT export는 이번 범위 밖.
- **한계**: 커밋 제목에 사람이 쓴 비밀은 패턴 기반 마스킹으로 못 잡는다(그래서 저장소는 허용 목록). `ro eval`에는 아직 수집기 항목이 없다(`ro/harden.py`에 다른 미커밋 변경이 있어 보류, 단위 테스트가 같은 불변식을 검증).

### Phase 3 구현 메모 (2026-10-22)

- **일간 통계** `python -m ro.stats [--days N]` → `~/.ro/stats/YYYY-MM-DD.json`. 개수·도구·프로젝트 이름만(원문 없음), 세션은 같은 `ref`의 최신 `rev`만.
- **주간 증류** `python -m ro.distill [--days 7] [--external claude|codex|agy] [--dry-run]`
  - 로컬(기본): 3일 이상 반복된 도구·프로젝트·엔진 → `kind="memory"` 후보(신뢰 보통).
  - 외부 모델(사용자 승인 2026-10-21, 증류 한정): 집계 통계만 읽기 모드 엔진에 전송. 한도는 **주 1회·4KB·후보 5개·160자**, 통계가 비면 호출 생략.
    응답은 JSON 후보로만 파싱·마스킹하여 대기열에 넣고(신뢰 낮음), 지시로 취급하지 않는다. 모델·비용 상한은 사용자가 따로 정하지 않아 엔진 기본 모델 + 위 한도로 둔다.
- **승인 → 기억**: `ro learn approve ID` 시 `kind="memory"`면 `memory/ro-model.md`에 출처·확인일·유효 90일·신뢰를 붙여 한 줄 추가. 자동 커밋 없음(diff 확인 후 사용자가 커밋). `ro learn`의 재계산은 대기 중인 memory 후보를 지우지 않는다.
- **`ro eval`** 항목 추가: 증류는 승인 전 기록 없음·원문 미전송·읽기 모드.
- **미검증**: 실제 수집 데이터가 없어(수집기 미허용) 외부 엔진 실호출·실데이터 사이클은 하지 않았다. 종료 조건("후보 → 승인 → 커밋" 한 사이클)은 합성 데이터 단위 테스트로만 확인.

### Phase 4 구현 메모 (2026-10-22)

- `python -m ro.tidy scan --root DIR [--stale-days 180] [--min-size 4096]` — **읽기 전용**. 내용 해시가 같은 중복(가장 오래된 것을 원본으로 유지)과 오래 수정 없는 파일을 `~/.ro/tidy/plan.json`에 제안(최대 200건, 큰 순).
- `apply ID...` — **id를 직접 지정한 항목만** `~/.ro/tidy/trash/<batch>/`로 이동(영구 삭제 없음). 계획 이후 크기·수정시각·해시가 바뀌었거나 루트 밖·심볼릭 링크면 건너뜀. 이동마다 `journal.jsonl`에 기록.
- `undo [BATCH]` — 해시 확인 후 원위치 복원. 원위치에 파일이 있으면 덮어쓰지 않고 건너뜀. `status`로 이력.
- 안전 경계: 루트는 홈의 하위 폴더만(`~/.ro` 제외). 제외 대상은 비밀 이름·숨김·`~$` 임시·프로젝트 폴더(`.git`, `package.json` 등)·심볼릭 링크·SKIP_DIRS. 영구 삭제(purge)는 의도적으로 만들지 않았다.
- 실제 `~/Downloads` 읽기 전용 스캔에서 오탐(소스 조각·Office 임시 파일)을 보고 `min-size` 4KB·프로젝트 폴더 제외·`~$` 제외를 넣었다. 중복 원본은 '오래됨' 제안에서도 뺀다.
- `ro eval`에 "읽기 전용 스캔·격리 후 복원 가능" 항목 추가.
- **실사용 검증(2026-10-22)**: `~/Downloads`의 동일 해시 사본 1건으로 apply → undo를 실제로 수행. 내용 해시·수정 시각은 복원됐으나 권한이 644→600으로 바뀌는 결함을 발견해, 이동 시 원래 권한을 저널(`mode`)에 기록하고 복원 때 되돌리도록 고침(이전 기록은 `mode`가 없어 그대로 둠). 사용자 폴더에서 여러 건·큰 파일·원위치 충돌 사례는 아직 해 보지 않았다.

### Phase 5 구현 메모 (2026-10-22)

- `python -m ro.revise [--days 30] [--min-n 5] [--dry-run]` — route·feedback 로그와 bench 점수로 **routing.toml 개정안**을 `kind="routing"` 후보로 학습 대기열에 넣는다. 승인 전에는 아무 파일도 바뀌지 않는다.
- 제안 조건(카테고리별, 현재 기본 엔진 대비): 두 엔진 표본 5건 이상 · 품질(첫 시도 수용률, 피드백 3건 미만이면 성공률)이 15%p 이상 높음 · 재시도율 악화 10%p 이하 · 중앙 소요시간 1.5배 이하.
  재시도 = 같은 요청이 30분 안에 다시 옴. **비용은 토큰이 기록되지 않아 소요시간으로 대리**한다(한계).
- bench ctx 점수는 근거 문구에만 함께 표시하고 조건에는 넣지 않는다(과제가 카테고리와 대응하지 않고, 엔진당 1회 실행이라 표본이 작음).
- `ro learn approve ID` → `routing.toml`의 해당 `engine` 한 줄과 `updated`만 수정. 제안 이후 현재 엔진이 바뀌었으면 거부(대기열 유지), 수정 결과는 `load_routing`으로 검증한 뒤 원자적으로 쓴다. 자동 커밋 없음(`git diff routing.toml` 확인 후 커밋).
- 모델(`model`) 변경은 제안하지 않는다 — 모델 이름은 확인 후에만 채운다는 기존 원칙 유지.
- `ro eval`에 "승인 전 routing.toml 불변" 추가.
- **미검증**: 실로그는 5건뿐이라(표본 부족) 실데이터 제안은 아직 나오지 않는다. 승인→반영→커밋 사이클은 합성 로그 테스트와 eval로만 확인.

## 5. 측정에서 얻은 설계 원칙 (2026-10-21, codex, 합성 프로젝트 5과제×3조건×3회)

- 컨텍스트는 대상 프로젝트를 모를 때 정확도를 크게 올렸다(ctx 1.00 / none 0.30). → `memory/ro-model.md`가 핵심 자산.
