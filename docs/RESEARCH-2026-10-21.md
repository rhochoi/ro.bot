# 오픈소스 조사: 가져다 쓸 것 vs 직접 만들 것

조사일: 2026-10-21. 설치·실행은 하지 않았다(읽기 전용 조사).
수치(★, 라이선스, 최근 푸시)는 같은 날 `gh api`로 확인한 값. 기능 설명은 웹 검색 결과이며
벤더 블로그가 섞여 있어 **의견으로 취급**한다. 도입 전 각 저장소의 코드·권한·네트워크 동작을 직접 읽을 것.

## 요약 판단

| 영역 | 판단 | 이유 |
|---|---|---|
| 개인 활동 측정 | **가져다 쓰기** (atuin, git) | 로컬 SQLite를 읽기 전용으로 읽으면 됨. 직접 만들 가치 낮음 |
| 컨텍스트 선택(Map 고도화) | **아이디어 차용 + 직접 구현** | aider의 repo map 방식(tree-sitter + PageRank). 코드 의존은 불필요 |
| 기억 | **아이디어 차용, 프레임워크는 보류** | 사용자 1명 규모에 벡터DB·그래프DB는 과함. 시간 유효성·출처 개념만 차용 |
| 엔진 오케스트레이션·평가 | **직접 유지** | 신뢰할 만한 재사용 대상을 못 찾음 |

## 1. 개인 활동 측정

| 프로젝트 | ★ | 라이선스 | 최근 푸시 | 비고 |
|---|---|---|---|---|
| [atuinsh/atuin](https://github.com/atuinsh/atuin) | 32,046 | MIT | 2026-10-21 | 셸 히스토리를 SQLite로 저장, 명령별 컨텍스트 기록. 동기화는 선택(끄면 로컬 전용) |
| [ActivityWatch/activitywatch](https://github.com/ActivityWatch/activitywatch) | 19,306 | MPL-2.0 | 2026-10-18 | 앱·창 사용 시간. 데이터는 기본적으로 localhost 서버에 저장 |
| [Jackenmen/aw-watcher-terminal](https://github.com/Jackenmen/aw-watcher-terminal) | 1 | MPL-2.0 | 2023-09-14 | 방치됨. 쓰지 않음 |

- **추천:** git 활동(이미 가능) → atuin(셸) 순. ActivityWatch는 창 제목이 민감 정보를 포함할 수 있어 마지막에, 수집 범위를 제한한 뒤 도입.
- **주의:** 셸 명령에는 비밀이 섞일 수 있다. ro로 가져올 때 `log.redact`를 반드시 거치고, atuin 동기화는 켜지 않는다.
- **연동 방식(제안):** ro가 atuin DB를 읽기 전용으로 열어 요약만 로그에 기록. 원본은 복사하지 않음.

## 2. 컨텍스트 선택 (Map 고도화)

| 프로젝트 | ★ | 라이선스 | 최근 푸시 | 비고 |
|---|---|---|---|---|
| [Aider-AI/aider](https://github.com/Aider-AI/aider) | 49,675 | Apache-2.0 | 2026-05-22 | repo map의 원조. 푸시가 5개월 전이라 활발도는 낮아짐 |
| [pdavis68/RepoMapper](https://github.com/pdavis68/RepoMapper) | 217 | MIT | 2025-12-08 | aider 방식의 MCP 서버/CLI 재구현. 소규모·1인 유지보수 |

- aider 방식: tree-sitter로 심볼 정의 추출 → 파일 간 참조 그래프 → PageRank로 중요도 → 토큰 예산에 맞춰 자름. ([설명](https://aider.chat/2023/10/22/repomap.html))
- 참고: Claude Code는 사전 인덱스 대신 에이전트 검색을 쓴다(검색 결과 기준). 어느 쪽이 내 프로젝트에 낫는지는 측정할 일.
- **추천:** 외부 코드를 의존성으로 넣지 말고 방식만 차용. 1차는 심볼 추출 없이도 `AGENTS.md`/`CLAUDE.md`·README·최근 커밋을 요약해 질문과 매칭하는 것부터.

- 벤치마크 수치(예: 한 블로그의 Zep 63.8% vs Mem0 49.0%)는 방법론을 확인하지 못해 **채택 근거로 쓰지 않는다**.
- **판단:** 이 프레임워크들은 다수 사용자·대량 기억을 가정한다. ro는 1인, 기억 수백 건 규모라 JSONL+규칙 파일로 충분하고, 사용자 데이터를 LLM/임베딩 호출에 넘기는 경로가 생기는 것이 오히려 위험.
- **차용할 개념:** (a) 기억마다 출처·시각·유효기간(Graphiti의 시간 모델), (b) 모순되면 새 증거가 이김, (c) 승인 전 후보 상태(이미 Learn에 있음).

## 4. 엔진 오케스트레이션·평가

- 검색에서 Bernstein, ADE, Ralph Harness, Ivy Tendril 등이 나왔지만, 이번에 `gh`로 저장소를 특정·검증하지 못했다(Bernstein은 검색 결과 없음). 문서 주장만 있으므로 **미검증**.
- 개인용 평가 하네스로 보이는 저장소는 ★0 수준(`Whamp/local-bench`, `walcz-de/coder-bench`)이라 신뢰·유지보수 근거 부족.
- **판단:** 지금 `ro/route.py`+로그 기반 평가를 직접 키우는 편이 낫다. 외부 오케스트레이터는 권한을 넓게 요구하는 경우가 많아(검색된 한 가이드도 상승된 권한 경고) 이 Mac의 개인 데이터와 같은 곳에서 돌리기엔 검증 비용이 큼.
