# 브랜치·커밋 규칙

확정: 2026-11-01 (사용자 결정). 브랜치는 작업대다. 보관함으로 쓰지 않는다.

## 원칙

- `main`은 항상 배포 가능한 상태다. main에 머지되면 `release.yml`이 날짜 버전 태그를 붙인다.
- PR 하나에 브랜치 하나. 머지되면 그 브랜치는 끝난다.
- 작업은 `git fetch` 뒤 `origin/main`에서 시작한다. 로컬 `main`은 낡았을 수 있다
  (2026-11-01, 로컬 main이 129커밋 뒤처진 줄 모르고 이미 삭제된 코드를 고친 일이 있었다).

## 브랜치 이름

| 누가 | 형식 | 예 |
|---|---|---|
| AI 세션 | `claude/<종류>-<주제>` | `claude/fix-distill-log`, `claude/docs-git-workflow` |
| 사람 | `<종류>/<주제>` | `fix/release-ci`, `exp/rive-pet` |

- 종류: `feat` `fix` `docs` `refactor` `test` `chore` `exp`(조사·실험, 머지하지 않을 수도 있음)
- 주제: 영문 소문자와 하이픈, 세 단어 안쪽.
- 앱이 붙인 자동 이름(`claude/what-to-do-next-41381a` 같은)은 첫 커밋 전에 `git branch -m claude/<종류>-<주제>`로 바꾼다.

## 커밋

- `종류(범위): 요약` (Conventional Commits). 범위는 모듈 이름(`pet`, `find`, `handoff` …).
- 커밋 하나에 의도 하나.

## PR과 머지

- main에는 PR로만 들어간다. 머지는 **스쿼시만** 쓴다.
- 스쿼시하면 PR 제목이 main의 커밋 메시지가 되므로, PR 제목도 커밋 형식으로 쓴다.

## 수명과 정리

- 머지되면 GitHub가 원격 브랜치를 지우고, 앱이 그 세션을 보관하면서 워크트리를 정리한다.
- 머지하지 않고 버리는 브랜치에 남길 커밋이 있으면 `archive/<원래 이름>` 태그를 달고 브랜치는 지운다.
  되살리기: `git switch -c <이름> archive/<이름>`.
- 조사·감사 결과물은 브랜치로 남기지 않는다. `docs/`에 머지하거나 archive 태그로 둔다.
- 주 1회 `bash scripts/git-tidy.sh`로 남은 것을 본다(기본은 보기만). 목록을 확인한 뒤 `--apply`로 정리한다.
  원격 브랜치와 태그는 이 스크립트가 지우지 않는다.

## 한 번만 하는 설정

- GitHub 저장소: 머지 후 브랜치 자동 삭제 켜기, 머지 방식은 스쿼시만 허용(머지 커밋·리베이스 끄기).
- Claude 앱: PR이 닫히면 세션 자동 보관.
