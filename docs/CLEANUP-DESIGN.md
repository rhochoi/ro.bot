# 정리 통합 설계안 — `ro tidy` + `ro organize` → 하나의 흐름

작성: 2026-10-22 · 상태: **설계 확정, C1~C5 구현됨**(결정 ①~④ 확정, §9 · 공용 탐지기 `ro/detect.py` · 구현 메모 §11). 근거는 `ro/tidy.py`·`ro/organize.py`·`ro/pet.py`(main `5a65723`)와 같은 날 실제 `~/Downloads` 정리 결과.

## 1. 목표와 완료 조건

파일 하나에 **제안은 하나만** 나오게 한다. 한 번 스캔하면 "어디로 옮길지(분류·이름)"와 "치워도 되는지(중복·풀린 압축·옛 버전)"가
같은 계획에 함께 나오고, 승인·되돌리기도 한 곳에서 한다. 안전 약속은 그대로: **제안 → 승인 → 이동(삭제 없음) → 되돌리기.**

완료 조건: `~/Downloads`에서 `ro organize scan` 한 번 → 이동·격리 항목을 각각 일부 승인 → `undo` 한 번으로 둘 다 원상복구.
같은 파일이 두 계획에 동시에 오르는 경우 0건. 펫 말풍선에서도 같은 흐름. `ro eval` 통합 항목 PASS.

## 2. 현재 상태 (확인한 사실)

| | `ro tidy` | `ro organize` |
|---|---|---|
| 하는 일 | 치울 후보를 `~/.ro/tidy/trash/`로 **격리** | 카테고리 폴더(`~/Documents/정리됨/…`)로 **이동 + 이름 변경** |
| 판단 | 중복(SHA-256)·풀린 압축(CRC)·옛 버전(`_vN`·`(N)`)·오래됨(180일) | 확장자·이름 규칙 + 본문 앞부분 키워드 → 카테고리, 날짜·제목 |
| 범위 | 하위 폴더까지 재귀 | **최상위 파일만**(폴더는 사용자가 묶은 단위) |
| 제외 | 숨김·비밀 이름·프로젝트 폴더·심링크·4KB 미만 | 숨김·비밀·**민감 이름(복구 코드·OTP·시드)**·**최근 10분 수정**·**다운로드 중**·iCloud 자리표시 |
| 계획/기록 | `~/.ro/tidy/plan.json`, `journal.jsonl` | `~/.ro/organize/plan.json`, `journal.jsonl` |
| 진입점 | CLI만 | CLI + **펫 말풍선**(쓰기 승인 게이트) + 설치 안내(`install.sh`) |

실사용에서 드러난 문제(2026-10-22):
- **같은 파일, 반대 제안.** `KCC 경비 내역 .xlsx` — organize는 "재무"로 보관, tidy는 "옛 버전"으로 격리 제안.
  계획·기록이 따로라 한쪽에서 옮기면 다른 쪽 계획이 낡고, 각자의 `undo`는 상대가 옮긴 파일을 모른다.
- **"오래됨"은 잡음.** tidy 후보 81건 중 77건이 오래됨이었고, 영수증·정산·재무 파일이 섞였다. 실제로 옮긴 10건 중
  7건(풀린 압축·옛 버전)은 사람이 골랐다 → 이후 탐지로 자동화(PR #16).
- **남길 쪽 선택이 기계적.** 감사 증빙 폴더 안 사본을 중복으로 지목(가장 오래된 파일을 원본으로 남기는 규칙 때문).
- tidy에는 organize의 안전 제외(최근 수정·다운로드 중·민감 이름)가 없다.
- 명령이 둘이라 무엇을 써야 할지 헷갈린다(설치 안내는 `organize`, 정리 대화는 `tidy`).

## 3. 핵심 설계 결정

1. **진입점은 `ro organize` 하나(결정 ①).** 펫·설치 안내가 이미 이것을 쓴다. `ro tidy`는 두 릴리스 동안 안내만 하는 별칭으로 남긴다
   (`ro tidy scan` → organize scan을 "치울 후보" 보기로 실행하고 새 명령을 알려 줌).
2. **파일마다 행동 하나(action).** 계획 항목은 `move`(분류 폴더로 이동·이름 변경) · `quarantine`(격리) · `keep`(그대로, 검토 필요 포함)
   중 하나만 가진다. 판정 순서가 곧 우선순위다(§4).
3. **중요 카테고리는 치우지 않는다.** organize가 `재무`·`계약·서류`로 분류한 파일은 오래됨·옛 버전 이유로 격리하지 않는다.
   내용이 완전히 같은 중복만 격리 후보가 되며, 그것도 `review`(사람 확인 필요)로 표시한다.
4. **"오래됨"은 정보로 강등(결정 ②).** 기본 계획에서 격리 제안을 만들지 않고 항목에 `오래됨 217일` 태그만 붙인다.
   `--stale` 옵션으로 지금처럼 격리 후보를 받을 수 있다.
5. **남길 쪽 선택 규칙 개선.** 중복·옛 버전에서 남길 파일은 ① 하위 폴더(사용자가 묶은 단위) 안의 것 ② 정리 폴더 안의 것
   ③ (옛 버전은) 가장 높은 vN, 없으면 최신 수정본 순. 최상위에 흩어진 사본을 먼저 치운다 — 증빙 폴더 문제 해결.
6. **범위:** 이동(`move`)은 지금처럼 최상위 파일만. 탐지(중복·풀린 압축·옛 버전)는 하위 폴더까지 보되, **격리 대상은 최상위 파일**로
   제한한다(폴더 안 파일은 남길 쪽으로만 쓰인다). `--deep`이면 폴더 안 파일도 격리 후보로 낸다.
7. **기록 하나, 되돌리기 하나.** 격리 파일은 `~/.ro/cleanup/trash/<batch>/`로 옮기고(결정 ④ — macOS 휴지통이 아니라
   되돌리기 기록과 같은 곳), `~/.ro/cleanup/journal.jsonl`에 `move`·`quarantine`·`restore`를 함께 남기고, `undo BATCH`는
   종류에 관계없이 원위치. 옛 `tidy`·`organize` 기록도 읽어서 예전 배치를 되돌릴 수 있게 한다(이전 호환).
8. **적용 직전 재확인은 공통.** 대상 파일(크기·수정시각·해시)과 남길 쪽(중복 원본·최신 버전·풀린 파일)이 그대로일 때만 실행.
9. **영구 삭제는 별도 단계(결정 ③).** 격리 폴더 비우기는 명시 명령 `ro organize trash --empty`로만 한다.
   - 대상은 격리된 지 **N일(기본 7일) 지난 배치만**(`--older 7d`로 조정). 그보다 최근 것은 목록에만 보이고 지우지 않는다.
   - 실행 전에 대상 배치·파일 수·용량을 보여 주고 **터미널에서 `yes` 입력으로 확인**한다(파이프·비대화 실행은 거부, `--yes` 옵션 없음).
   - 지운 배치는 기록에 `purge`로 남기고 더 이상 `undo` 대상이 아님을 표시한다. 펫 말풍선에는 넣지 않는다(용량 표시만).

## 4. 판정 파이프라인 (한 번의 scan)

```
후보 수집 (공통 제외: 숨김·비밀·민감 이름·심링크·프로젝트 폴더·최근 10분·다운로드 중·iCloud 자리표시)
  │
  ├─ 1. 완전 중복 (크기→SHA-256)          → 남길 쪽 규칙(§3-5) 밖의 사본: quarantine  [재무·계약이면 review]
  ├─ 2. 풀린 압축 원본 (항목 전부 CRC 일치)  → zip: quarantine, 풀린 파일은 이후 단계에서 보호
  ├─ 3. 옛 버전 묶음 (_vN·(N)·_N)          → 최신 외: quarantine  [재무·계약이면 keep + 표시만]
  ├─ 4. 분류·이름 (L1 규칙 → L2 키워드)     → move (확신도 < 0.6이면 keep/review)
  └─ 5. 오래됨 태그                       → 정보만 (--stale일 때만 quarantine)
```
- 1~3에서 남길 쪽으로 정해진 파일은 4단계에서 정상적으로 `move` 제안을 받는다(예: 기획안 v13 → `문서/2026-…_기획안.docx`).
- 분류(4)는 1~3보다 뒤지만 **중요 카테고리 보호(§3-3)를 위해 분류 결과는 1~3 판정 시에도 참조**한다(분류 → 판정 순으로 계산하고, 출력 우선순위만 위와 같이).

## 5. 계획 형식 (`~/.ro/cleanup/plan.json`)

```json
{"root": "...", "dest_root": "...", "created": "...", "items": [
  {"id": "3e0ce478", "path": ".../리모 노션 로고.zip", "size": 67584, "mtime": 0, "sha": "…",
   "action": "quarantine", "kind": "extracted", "keep": ".../리모 노션 로고",
   "category": "압축·설치", "dest": null, "confidence": 1.0, "review": false,
   "tags": ["오래됨 210일"], "reasons": ["압축 안 파일이 모두 리모 노션 로고/ 폴더에 풀려 있음(CRC 일치)"]}
]}
```
`kind`: `duplicate`·`extracted`·`version`·`stale`(격리) / `classified`(이동) / `review`·`important`(보관).

## 6. 명령

```
ro organize scan  [--root ~/Downloads] [--deep] [--stale [--stale-days 180]]
ro organize show  [--action move|quarantine|keep] [--category 재무] [--kind extracted] [--review]
ro organize edit  ID [--category 문서] [--name "제목"] [--action keep|move|quarantine]
ro organize apply ID... | --category 재무 | --kind extracted     # 지정한 것만. review 항목은 edit로 확정 후
ro organize undo  [BATCH] | status
ro organize trash [--empty [--older 7d]]                          # 격리 용량 보기 / N일 지난 배치 비우기(확인 질문)
ro tidy …                                                         # 별칭: 안내 후 organize로 위임(2 릴리스)
```
`scan` 출력 첫 줄 예: `이동 23건 · 치울 후보 5건(51MB 확보 가능) · 검토 4건 — 아무것도 바꾸지 않았습니다`.

## 7. 펫 연동

- 말풍선 요약: `정리 23 · 치울 후보 5(51MB)`. 지금의 카테고리별 승인 버튼에 **"치울 후보" 묶음(종류별)**을 추가한다
  (`풀린 압축 2`, `옛 버전 1` …). 같은 쓰기 승인 게이트(`queue_organize_apply`)를 재사용하고 `kind` 인자만 더한다.
- 되돌리기 버튼은 하나(최근 배치). 격리 비우기는 말풍선에 넣지 않는다 — 격리 용량만 보여 주고 `ro organize trash --empty`를 안내(결정 ③).

## 9. 결정 (확정 2026-10-22)

1. **명령 이름:** `ro organize` 유지. 펫·설치 안내가 이미 사용 중이라 바꾸지 않는다. `ro tidy`는 2 릴리스 동안 안내용 별칭.
2. **오래됨:** 격리 제안을 만들지 않고 정보 태그로만 표시. 필요하면 `--stale`로 기존처럼 후보를 받는다.
3. **격리 비우기(영구 삭제):** ro에 넣되 명시 명령 `ro organize trash --empty` + 터미널 확인 + N일(기본 7일) 지난 배치만. 펫에는 넣지 않는다.
4. **격리 위치:** `~/.ro/cleanup/trash/<batch>/`. macOS 휴지통이 아니라 되돌리기 기록과 같은 곳에 둬서 `undo`·`purge` 상태를 한 곳에서 관리한다.

## 10. 남은 위험

- **계획 이전 호환:** 옛 `tidy/plan.json`·`organize/plan.json`은 새 apply에서 쓰지 않는다(다시 scan 안내). 옛 기록 undo만 지원.
- **분류 오판의 파급:** 분류가 틀려 `재무`를 놓치면 보호(§3-3)도 빠진다 → 격리 기본값을 보수적으로(완전 중복·풀린 압축 우선, 옛 버전은 review 비율 높게).
- **펫 UI 변경 범위:** 말풍선 공간이 좁다 — 치울 후보는 종류별 합계만 보이고 상세는 CLI/`show`로.
- **성능:** 재귀 해시는 큰 폴더에서 느릴 수 있다 → 크기 같은 파일만 해시(현행), 압축은 항목 5000개 초과 시 건너뜀(현행).
- 이름 규칙 기반 탐지(옛 버전)는 내용 차이를 모른다 → 항상 승인제, 학습(C7)도 제안까지만.
- 격리 위치가 `~/.ro` 안이라 Finder 휴지통에서는 보이지 않는다 → `scan`·`status`·펫에 격리 용량을 항상 표시하고 `trash`로 목록을 보여 준다.
- 비우기는 되돌릴 수 없다 → N일 대기 + 확인 질문 + 비대화 실행 거부로 실수 여지를 줄이되, 그 이상의 복구 수단은 없다.

## 11. 구현 메모

**C2 (2026-10-22)**
- 중요 파일 보호는 카테고리(`재무`·`계약·서류`)만으로는 부족했다: 표·이미지 등은 키워드 세분을 하지 않아
  `KCC 경비 내역 .xlsx`가 `표·데이터`로 분류된다. 그래서 **이름에 재무·계약 낱말**(분류 키워드 + 경비·정산·결산·재무·회계·미수금·세금·예산·영수)이
  있어도 같은 보호를 준다. 분류 자체는 바꾸지 않는다.
- 확신도가 낮은 항목은 §5의 `keep/review` 대신 기존처럼 `action: move` + `review: true`로 둔다(edit로 확정하는 기존 흐름·펫 표시 유지).
- 치울 후보(`quarantine`)는 아직 organize로 격리하지 않는다. `apply`는 move 항목만 옮기고, 카테고리 일괄 선택·펫 이동 버튼에서도 빠진다.
  `edit --category`로 위치를 정하면 move 항목이 된다. 이전 형식 계획(action 없음)은 move로 본다.
- **C3에서 처리할 것:** 남길 쪽이 최상위 파일이면 그 파일도 move 제안을 받는다. 같은 배치에서 먼저 옮겨지면 `kept_ok`가 원래 경로를 못 찾아
  치울 후보가 건너뛰어진다 → C3 apply는 남길 쪽의 새 위치를 journal로 따라가거나, move를 quarantine 뒤에 실행해야 한다.

**C3 (2026-10-22)**
- `apply`는 치울 후보를 먼저 `~/.ro/cleanup/trash/<batch>/<id>-<이름>`로 격리(0600, 원래 권한 기록)하고 그다음 이동한다.

**C4 (2026-10-22)**
- `show --action move|quarantine|keep --kind …` 필터. `edit ID --action keep|move|quarantine`:
  재무·계약 중복(`review`)은 `--action quarantine`으로 확정(탐지 근거 `kind`·`keep`은 유지 → 적용 직전 재확인도 그대로),
  탐지 근거가 없는 파일을 직접 치울 후보로 지정하면 `kind: manual`. `keep`/`quarantine`과 `--category`·`--name`은 함께 쓸 수 없다.
- `ro tidy`는 별칭: 안내(stderr) 후 `scan`→`organize scan --stale`, `apply`·`undo`·`status`→같은 organize 명령. `--min-size`는 무시.
  정리 대상이 최상위 파일로 바뀐 점을 안내 문구에 적었다. 라이브러리 `ro/tidy.py`(`walk`·`check_root`·`python -m ro.tidy`)는 남아 있다.
- 계획 파일은 `~/.ro/cleanup/plan.json`. 불러올 때 새 위치가 없으면 예전 `~/.ro/organize/plan.json`을 읽고, 다음 저장(scan·edit)부터 새 위치에 쓴다
  → 업그레이드 직후에도 펫의 정리안이 사라지지 않는다.
- README의 organize·tidy 두 줄을 한 줄로, 설치 안내의 정리 줄도 통합 흐름으로.
- `ro eval`에 "정리 통합" 항목(파일당 제안 하나·재무 옛 버전 보관·격리+이동 한 배치 후 undo 원상복구·예전 tidy 배치 undo) — undo나 재무 보호를 끄면 FAIL하는 것 확인. 전체 18개.
