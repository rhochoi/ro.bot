# 펫 메뉴 막대 모드 · CPU 걸음 설계안 (06 + 07)

결정(2026-10-23): 아래 "확정 결정"대로 구현한다. 대상은 `ro/pet_mac.swift`(호스트)와 `ro/pet.py`의 `PET_HTML`(웹 펫).

## 확정 결정

| 항목 | 결정 | 이유 |
|---|---|---|

## 06 — 메뉴 막대로 보내기

### 모드 상태

```
desktop ──(위쪽 80px 구역에서 놓기)──▶ menubar
menubar ──(아이콘 끌어 내리기 · '데스크톱에 꺼내기' · 패널 ⋯ 메뉴)──▶ desktop
```

- 전환은 `setMode(_:animated:)` 하나로만 한다. 펫 창 `orderOut`/`orderFront`, `statusItem.isVisible`, 저장을 함께 처리한다.
- 저장: `UserDefaults(suiteName: "ro.pet")`의 `ro.mode` = `desktop` | `menubar`. 호스트는 번들 없는 `swiftc` 실행 파일이라 `.standard` 도메인이 실행 파일 이름에 묶인다.
- 저장값은 동작 상태일 뿐 기억이 아니다. `~/.ro/`에 쓰지 않는다.

### 드래그 중 (01 잡기 · 02 가까이)

기존 `startNativeDrag` 타이머(8ms) 안에서 처리한다.

- `d = screen.visibleFrame.maxY - mouse.y`, `d < 80`이면 구역 안이다.
- 구역에 들어오면 `statusItem.isVisible = true`(자리 열림), 나가면 `false`.
- 진행률 `p = 1 - d/80`을 `window.onHostDockProgress(p)`로 넘긴다. 크기 `lerp(1, 0.22, p)`, 들어 올리기(y −6, scale 1.04), 위를 보는 눈은 CSS에서 처리한다. 창 크기는 바꾸지 않는다.

### 놓기 (03)

- 구역 안: `statusItem.button.window.frame`을 목표로 펫 창을 280ms ease-out으로 옮기고 `orderOut`, 이어서 `setMode(.menubar)`. 창 프레임에는 spring이 없으므로 탄성은 JS 크기 변화로 낸다. 착지 바운스 1회는 템플릿 이미지 2~3장 교체.
- 토스트 "메뉴 막대로 옮겼어요 · 아이콘을 끌어 내리면 다시 꺼낼 수 있어요".
- 구역 밖: 원래 자리로 돌아간다(현재 동작).

### 메뉴 막대에서 (04)

- `statusItem.menu`는 비우고 `button.sendAction(on: [.leftMouseDown])`로 직접 처리한다(`menu`가 있으면 액션이 오지 않는다).
  - 제자리에서 떼면 메뉴를 연다.
  - 아래로 24px 넘게 끌면 펫 창을 마우스 위치에 띄우고 `startNativeDrag`로 넘긴다(끌어 내리기).
- 메뉴는 `NSMenu`: 첫 줄은 `NSMenuItem.view`로 "오늘 N건 기록 · CPU % · 걸음 단계", 그 아래 패널 열기 ⌘K · CPU 따라 걷기 · 데스크톱에 꺼내기 · 종료. 바깥 클릭·esc 닫힘은 시스템이 한다.
- 패널 열기는 기존 `toggleBubble`을 재사용하고 펼친 창을 아이콘 아래에 붙인다.
- 상태 숫자는 새 HTTP 경로 없이 웹이 폴링 때마다 `notifyHost({type: "status", today, ...})`로 넘긴다.
- `statusItem.autosaveName = "ro.pet"`으로 ⌘-드래그 순서 변경을 허용한다.

### 웹 쪽

- `onHostDockProgress(p)`, `onHostDocked()` 추가.
- 패널 ⋯ 메뉴에 "데스크톱에 꺼내기" → `notifyHost({type: "mode", mode: "desktop"})`.
- 모두 `isNativeHost`로 감싼다(브라우저 모드 회귀 방지, `test_browser_mode_fallbacks`).

### 주의할 점

- 노치: 넣은 직후 `button.window.occlusionState.contains(.visible)`가 아니면 토스트로 알리고 데스크톱으로 되돌리기를 제안한다.
- 전체 화면: 메뉴 막대가 숨으면 아이콘도 시스템이 숨긴다.

## 07 — CPU에 맞춰 걷기

### 파이프라인

```
CPUSampler (Swift, 1초, Timer.tolerance 0.3)
  host_statistics(HOST_CPU_LOAD_INFO): (USER+SYSTEM+NICE) / 전체 틱, UInt32 &- 뺄셈
  → 최근 3개 중앙값 → 지수 평균 α=0.3 → 4단계 판정(경계 20/50/80, 모든 경계 ±5% 히스테리시스)
  → TempoController: 현재 사이클이 끝날 때만 단계 반영
       ├ 펫: CPU 걸음을 적용하지 않는다 (6단계에서 넣었다가 되돌림, 3d33fb8 참고)
       └ 메뉴 막대: 템플릿 프레임 4장 교체, 최대 0.8초 사이클, 가려지면 갱신 중단
  상한: 저전력 모드 → '보통'(1.6초)까지 · 동작 줄이기 → 걷지 않고 메뉴에 CPU %만
```

| 단계 | 다듬은 CPU | 사이클 | 펫 배속 | 메뉴 막대 사이클 | 표현 |
|---|---|---|---|---|---|
| 느긋 | 0–20% | 3.2초 | ×1 | 3.2초 | 아이콘이 제자리에서 낮게 콩 (1pt) |
| 보통 걸음 | 20–50% | 1.6초 | ×2 | 1.6초 | |
| 바쁨 | 50–80% | 0.8초 | ×4 | 0.8초 | 층이 더 크게 흔들림 |
| 과열 | 80–100% | 0.4초 | ×8 | 0.8초 | 눈을 가늘게 |

### 지켜야 할 구현 사실 (실측, 2026-10-23, 8코어 Mac)

- `cpu_ticks` 순서는 USER, SYSTEM, **IDLE**, NICE. idle은 인덱스 2다. 잘못 집으면 100%로 나온다.
- 틱 카운터는 `natural_t`(UInt32). 업타임 11.5일에 약 5.9억이라 몇 달 켜 두면 한 바퀴 돈다. 반드시 `&-`로 뺀다.
- `proc_pid_rusage`의 `ri_user_time`/`ri_system_time`은 mach 틱이다(이 Mac의 timebase 125/3). `mach_timebase_info`로 변환한다.
- 프로세스 767개 중 170개는 rusage를 읽을 수 없다(시스템·root).
- 전체 CPU %는 코어 수로 나뉜다. 8코어에서 한 코어를 꽉 채운 프로세스는 전체 12%로 '느긋'이다. 의도된 한계로 둔다.

### 템포 적용 규칙 (웹)

- 펫은 WKWebView 안의 CSS 키프레임이라 호스트 `CALayer.speed`로는 바꿀 수 없다고 본다(WebKit이 별도 프로세스에서 합성). `animation-duration` 변경은 위상이 튄다.
- 6단계에서 웹 펫에 `body[data-gait]` 방식으로 넣었으나(3d33fb8), 데스크톱 펫은 움직일 필요가 없다는 결정으로 되돌렸다. 아이콘(7단계, 2026-10-24 시안 '바쁠수록 자주 뛴다'): 걷기 4프레임이 툭툭 끊겨 보여 점프로 바꿨다. 템플릿 3장(f1 웅크림·f2 솟음·f3 정점)을 사이클의 0·30·45·60·75% 시점에 f1·f2·f3·f2·f1로 바꾸고, 남은 25%는 바닥에서 쉰다. 빠르기는 착지(f1)할 때만 바꾼다. 점프 높이 1.0/1.6/2.2/1.0pt(과열은 낮고 잦게, 가는 눈), 캔버스 18×18pt.
- 아이콘은 메뉴 막대 모드이고 가려지지 않았을 때만 그린다(`didChangeOcclusionState` 구독). 동작 줄이기면 멈춘 아이콘과 메뉴의 CPU %만, 저전력이면 보통 걸음까지.

### 과열 알림

```
원시 CPU 60초 이동 평균 ≥ 85% (그때만 프로세스 스캔)
  → proc_listallpids + proc_pid_rusage 2회(2초 간격), timebase 변환
  → proc_pidpath 기준 가장 바깥 .app으로 묶음 (Chrome Helper들 → Chrome)
  → 1위 앱 몫 > 읽지 못한 몫(전체 바쁨 − 읽은 합)일 때만 앱 이름, 아니면 이름 없이
  → 카드 "Mac이 힘들어해요" [활동 모니터 열기] [오늘은 그만]
```

- 표시(8단계 구현): 네이티브 카드 하나를 데스크톱 모드는 펫 옆, 메뉴 막대 모드는 아이콘 아래에 30초 띄운다. 펫 창이 숨은 메뉴 막대 모드에서도 같은 카드를 쓰려고 웹 카드 대신 네이티브로 했다. 번들 없는 실행 파일이라 시스템 알림은 쓰지 않는다.
- 문구: "가장 많이 쓰는 앱: <앱> (CPU N%) · 1분째 바빠요". N은 메뉴와 같은 Mac 전체 대비 %다(활동 모니터의 코어당 %와 다름). 이름을 못 대면 "1분째 CPU N%로 바빠요 · 어떤 앱인지는 확인할 수 없어요".
- 한 번 울린 뒤에는 60초 평균이 75% 아래로 내려가야 다시 울릴 수 있다.
- 빈도: 같은 앱은 하루 1회, '오늘은 그만'은 그날 전체를 끈다. 날짜·앱 이름은 `UserDefaults` 동작 상태로만 두고 로그·엔진·`~/.ro/`에 남기지 않는다(원칙 1·2).
- 활동 모니터 열기: `NSWorkspace`로 `com.apple.ActivityMonitor`를 연다.
- 온도 신호가 필요하면 `ProcessInfo.thermalState`(공개 API)를 보조로 쓴다. CPU %만으로 '과열'이라 부르지 않는다.

### 상태 변화

- 화면 꺼짐·잠금(`screensDidSleep`, `sessionDidResignActive`): 측정·애니메이션 정지, 깨어나면 평균과 60초 창 초기화.
- 저전력(`NSProcessInfoPowerStateDidChange`), 동작 줄이기(`accessibilityDisplayOptionsDidChangeNotification`): 알림을 구독해 즉시 반영한다.

### 자기 부하

- 목표(2026-10-24 결정): Ro 프로세스 전체(파이썬·호스트·WebKit GPU/WebContent/Networking) 합산이 **Mac 전체 대비** CPU 1% 미만. 숫자는 `proc_pid_rusage`로 잰다.
- 가장 무거운 후보는 CPU 측정이 아니라 기존 배경 밝기 샘플러(0.6초마다 화면 캡처 + 픽셀 64개 읽기)다. 함께 잰다.

### 실측 결과 (9단계, 2026-10-24, 8코어 Mac, 60초씩, 코어 하나 기준 %)

| 상황 | Python | 호스트 | WebKit GPU | WebContent | Networking | 합계 | Mac 전체 대비 |
|---|---|---|---|---|---|---|---|
| 메뉴 막대 모드 (아이콘 점프, 숨은 페이지는 WebKit이 타이머를 늦춤) | 0.01 | 0.87 | 0.00 | 0.00 | 0.01 | 0.89 | 0.11 |
| 데스크톱 모드, 고치기 전 (상태 폴링 0.45초) | 1.17 | 1.61 | 0.77 | 1.45 | 1.27 | 6.26 | 0.78 |
| 데스크톱 모드, 말풍선 닫힘 폴링 2초 (3회 측정) | 0.32~0.38 | 1.24~1.33 | 0.73~0.86 | 0.95~1.13 | 0.31~0.37 | 3.75~3.88 | 0.47~0.49 |

- 고친 것: 말풍선이 닫혀 있을 때 `/api/state` 폴링을 0.45초에서 2초로 (`setPollRate`). 표정 변화가 최대 2초 늦게 보인다.
- 배경 밝기 타이머를 0.6초 → 2초로 늘려 봤지만 차이가 없어(3.88%) 되돌렸다. 샘플러를 끈 빌드와 재질을 고정한 빌드로도 나눠 쟀지만 실행마다 폴링 상태가 섞여 결론을 내지 못했다.
- 두 모드 모두 목표(Mac 전체 대비 1% 미만)를 지킨다: 메뉴 막대 0.11%, 데스크톱 0.47~0.49%. 코어 하나 기준으로는 데스크톱이 약 3.8%이고, 남은 몫은 호스트(산책·배경 밝기)와 숨쉬기 CSS 애니메이션(GPU·WebContent)이다.
- 측정 방법: `proc_pid_rusage`(mach 틱 → timebase 변환)로 파이썬·호스트와, 호스트와 같은 초에 뜬 WebKit GPU·WebContent·Networking 프로세스를 60초 동안 합산. WebKit XPC는 책임 프로세스(responsibility)가 호스트로 잡히지 않아 시작 시각으로 찾았다.

### 아이콘 픽셀 (9단계)

- 2x(레티나)는 모든 단계·프레임이 선명하다. 1x에서는 0.8pt 층 사이와 1.3pt 눈이 회색으로 번지고 과열 눈이 거의 사라졌다.
- 고친 것: 그릴 때 기기 픽셀에 맞춘다. 크기와 위치를 따로 반올림하고, 층은 받침부터 쌓아 층 사이를 최소 1px로, 눈은 높이를 내림해 원래 중심에 놓는다.
- 남은 것: 1x의 보통·바쁨 웅크림(f1)에서 오른눈이 1px로 작아진다. 순간 프레임이라 두었다.

## 시뮬레이션 요약 (합성 트레이스, 10분, 1초 샘플)

| 트레이스 | 원시값 단계 전환 | 지수 평균만 | 확정 파이프라인 |
|---|---|---|---|
| 한가 + 순간 튐 | 44 | 42 | 4 |
| 50% 근처 | 298 | 140 | 13 |
| 빌드(90%, 40초마다 6초 60%) | 33 | 29 | 29 (실제 부하 변화) |

- 반응: 5% → 90% 계단에서 '과열' 도달까지 약 7초 + 사이클 끝 대기 최대 3.2초.
- 지수 평균 α=0.3만으로는 순간 튐을 거르지 못한다(70% 한 번이 평균을 21 올린다). 중앙값 단계가 필요하다.
