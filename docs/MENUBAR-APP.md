# 메뉴바 앱 설계안 (배포용)

결정(2026-10-22): macOS 메뉴바 앱으로 배포한다. 엔진은 사용자가 설치·로그인한 CLI(claude·codex·agy)를 호출한다(BYO CLI).
이 문서는 제안이다. 구현·배포 전에 아래 "확인 필요"를 먼저 해소한다.

## 원칙 (제품 약속)

- 화면 캡처·화면 녹화·접근성 권한을 요구하지 않는다. 입력은 텍스트(git, 셸, 엔진 세션, 일정, 시리얼)뿐이다.
- 기본값은 읽기 전용이며 수집 항목은 모두 꺼진 상태로 시작한다. 사용자가 항목별로 켠다.
- 엔진으로 나가기 전에 전송 내용을 미리 보여 준다(기존 `ask --dry-run`).
- 비밀값은 저장하지 않는다. 앱은 키·토큰을 받지 않는다(CLI가 각자 로그인 상태를 관리).

## 화면 구성 (최소)

1. **메뉴바 아이콘 → 팝오버**: 질문 입력창 1개.
2. **전송 미리보기**: "이 내용이 claude로 전송됩니다" + 마스킹된 컨텍스트 + [보내기] [취소].
3. **답변 영역**: 답변, 사용 엔진 표시, 👍/👎(= `ask.feedback`).
4. **설정**: 수집 항목 토글, 엔진 연결 상태(설치·로그인 감지), 로그 열기/삭제.
5. **첫 실행**: "수집하는 것 / 수집하지 않는 것" 한 장, CLI 설치 안내.

## 구조

- 기존 `ro/` 파이썬 코어는 유지하고, 앱은 얇은 UI 껍데기로 둔다.
  - 질문: `ask.plan(...)` → 미리보기 → `ask.execute(plan)` → `ask.feedback(...)`.
  - 지도: `mapper`, 점검: `harden`(audit), 회귀: `eval`.
- 앱↔코어 연결: 앱이 번들된 파이썬 코어를 로컬 프로세스로 호출한다(네트워크 포트 열지 않음). 실제 구현 방식(Swift 앱 + 번들 파이썬 vs. 코어 재작성)은 별도 결정.
- 데이터 위치: 사용자별 `~/.ro/`(권한 0700/0600). 개인 설정(`identity/`, `memory/rog-model.md`, `~/.codex/AGENTS.md` 참조)은 배포본에서 제외하고 기본 템플릿만 포함한다.
- `routing.toml`은 기본 템플릿으로 배포하고 사용자가 수정할 수 있게 한다.

## 코드 쪽 선행 과제

- `route.ENGINES` 감지: 엔진 CLI가 없거나 로그인 만료일 때 앱이 이해할 수 있는 오류 코드로 반환(현재는 일부만 처리).
- 개인 경로·개인 설정이 코어에 하드코딩된 곳 점검 후 설정화.
- 수집기(`collectors`)에 항목별 on/off 설정 추가(기본 off).
- 로그 보관·삭제 UI에 대응하는 코어 함수(전체 삭제, 기간 삭제).

## 확인 필요 (코드로 검증 안 됨)

- 각 CLI의 약관이 제3자 앱의 호출·재배포를 허용하는지(공식 문서 확인, 확인일 기록).
- 직접 배포(DMG) 시 서명·공증 절차와 번들된 파이썬의 서명 호환성.
- 앱스토어 샌드박스는 임의 CLI 실행과 충돌 가능성이 높아 1차 범위에서 제외.

## 단계

1. 코어 정리(위 선행 과제) + 테스트.
2. 프로토타입 메뉴바 UI: 질문 → 미리보기 → 답변.
3. 설정·첫 실행 화면, 로그 삭제.
4. 서명·공증, 소수 사용자 시험 배포.
